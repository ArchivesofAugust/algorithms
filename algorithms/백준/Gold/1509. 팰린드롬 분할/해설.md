# 1509. 팰린드롬 분할 — 해설

## 핵심 아이디어

문자열을 팰린드롬 조각들로 나누는 최소 개수를 구하는 문제는 **두 단계 DP**로 풀린다:
1. 모든 구간이 팰린드롬인지 미리 계산 (10942와 동일한 구간 DP)
2. 그 결과를 이용해 "최소 분할 개수"를 구하는 1차원 DP (구간 최적 분할 문제, 마치 최단 경로 느낌)

## 접근 방법

**1단계 — `isPal[i][j]`**: 10942와 완전히 같은 점화식.
- `isPal[i][i] = true`
- `isPal[i][i+1] = (s[i] == s[i+1])`
- `isPal[i][j] = (s[i] == s[j]) && isPal[i+1][j-1]`

**2단계 — `cut[i]`**: `s[i..n-1]` (인덱스 i부터 끝까지)를 팰린드롬 조각들로 나눌 때 필요한 최소 조각 수.
- `cut[n] = 0` (빈 문자열은 0개의 조각)
- `cut[i] = min( 1 + cut[j+1] )`, 모든 `j >= i`에서 `isPal[i][j]`가 true인 경우
  - 즉, `s[i..j]`를 팰린드롬 조각 하나로 떼어내고, 나머지 `s[j+1..n-1]`은 이미 계산된 `cut[j+1]`을 재사용

`i`를 뒤에서부터(`n-1`→`0`) 채워야 `cut[j+1]`(항상 `i`보다 뒤)이 먼저 계산돼 있다.

정답은 `cut[0]`.

## 시간/공간 복잡도

- 1단계: O(N²) 시간/공간
- 2단계: O(N²) 시간(각 `i`마다 `j`를 훑음), O(N) 추가 공간
- 전체: O(N²), N ≤ 2500이므로 최대 625만 — 여유 있음

## 헷갈렸던 점 / 주의할 점

- 원래 풀이(기존 `.cc`)는 재귀 + 메모이제이션(top-down)으로 짰지만, N=2500이면 재귀 깊이가 최악 2500까지 갈 수 있어 스택 오버플로우 위험이 있다 — Java에서는 특히 기본 스택 크기가 작아 위험. 그래서 이번엔 **바텀업(반복문)**으로 짜서 재귀 깊이 문제를 원천 차단했다.
- `cut[i]`를 "i부터 끝까지 자르는 최소 조각 수"로 정의할지 "0부터 i까지"로 정의할지에 따라 순회 방향이 반대가 된다 — 방향을 명확히 정하고 시작해야 인덱스 실수를 줄인다.
- **팰린드롬 시리즈 정리**:
  - 10988: 단일 문자열이 팰린드롬인가? → 투 포인터 O(N)
  - 1213: 팰린드롬을 "만들 수 있는가" + 사전순 최소 구성 → 그리디(홀수 카운트 조건)
  - 10942: 모든 구간이 팰린드롬인가? (많은 질문) → 구간 DP `isPal[i][j]`, O(N²) 전처리 + O(1) 질문
  - 1509: 팰린드롬 조각으로 최소 분할 → `isPal[i][j]` 위에 얹은 1차원 최적 분할 DP
  - 즉 **판별(투 포인터) → 판별의 확장(구간 DP) → 그 위에 최적화 DP를 얹기**라는 하나의 흐름으로 이어진다.
