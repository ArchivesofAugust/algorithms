## 관통하는 흐름

### 1. 판별 — "이 문자열은 팰린드롬인가?" (10988)

가장 기본 연산: **투 포인터**. 양 끝에서 시작해 안쪽으로 좁혀가며 비교. O(N) 시간, O(1) 공간.

```
isPalindrome(s, left, right):
    if left >= right: return true
    if s[left] != s[right]: return false
    return isPalindrome(s, left+1, right-1)
```

이 재귀 관계 `isPal(i, j) = (s[i]==s[j]) && isPal(i+1, j-1)`가 뒤의 모든 문제에서 반복해서 등장하는 핵심 점화식이다.

### 2. 구성 — "팰린드롬을 만들 수 있는가?" (1213)

판별이 아니라 **주어진 재료로 팰린드롬을 구성**하는 문제. 팰린드롬의 구조적 제약(중앙 기준 대칭)에서 조건을 뽑아낸다:
- 홀수 개수인 문자가 2개 이상이면 구성 불가능
- 가능하면 그리디하게 절반을 채워 사전순 최소를 만든다

"판별"의 핵심 조건(대칭)을 거꾸로 이용해 "구성 가능 조건"을 유도하는 사고 전환이 포인트.

### 3. 판별의 확장 — "모든 구간이 팰린드롬인가?" (10942)

10988의 재귀 관계 `isPal(i,j) = (s[i]==s[j]) && isPal(i+1,j-1)`를 **단일 구간이 아니라 모든 (i,j) 쌍에 대해 미리 전부 계산**해두는 것이 구간 DP다.

- `dp[i][j]` 테이블에 O(N²) 시간/공간으로 전처리
- 이후 질문마다 O(1) 조회
- 짧은 구간부터 채워야 함 (`dp[i+1][j-1]`이 먼저 필요하므로) — 길이 기준으로 순회

핵심 전환: "한 번 판별하는 함수"에서 "모든 경우를 표에 저장해두는 DP"로.

### 4. 최적화 — "최소 몇 조각으로 나눌 수 있는가?" (1509)

10942의 `isPal[i][j]` 테이블을 **재료**로 삼아, 그 위에 "최소 분할 개수"를 구하는 **1차원 최적화 DP**를 얹는다.

- `cut[i]` = `s[i..n-1]`을 팰린드롬 조각들로 나누는 최소 개수
- `cut[i] = min(1 + cut[j+1])`, `isPal[i][j]`가 true인 모든 `j`에 대해
- 구간 판별(2단계 DP) 위에 최적 분할(1단계 DP)을 쌓는 전형적인 "DP 위에 DP" 패턴

## 전체 그림

```
투 포인터 판별 (10988)
        │  재귀 관계를 모든 구간으로 확장
        ▼
구간 DP: isPal[i][j] (10942)
        │  재료로 삼아 그 위에 최적화 DP를 쌓음
        ▼
1차원 최적 분할 DP: cut[i] (1509)

별도 축: 판별 조건을 뒤집어 구성 조건으로 (1213, 그리디)
```

## 자주 하는 실수

- 구간 DP에서 순회 순서를 헷갈려 아직 계산 안 된 `dp[i+1][j-1]`을 참조하는 것 — 길이(또는 구간 크기) 기준으로 짧은 것부터 채워야 한다.
- 길이 1, 2 base case를 길이 3 이상 점화식에 억지로 넣으려다 인덱스가 꼬이는 것 — base case는 항상 분리.
- N이 클 때(1509의 N≤2500) 재귀 기반 DP는 스택 오버플로우 위험 — 바텀업(반복문)으로 짜는 습관.
- 팰린드롬 "판별"과 "구성"은 서로 다른 방향의 문제라는 것 — 판별은 주어진 것을 확인, 구성은 조건을 만족하는 것을 만들어내는 것. 접근 방식(투 포인터/DP vs 그리디)이 완전히 다르다.
